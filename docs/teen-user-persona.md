# 青少年用户画像｜Teen Persona

## Persona at a glance

> 本画像用于课程原型的认知走查，是基于项目情境提出的**研究假设**，不是已经被真实用户验证的结论。

| 字段 | 内容 |
|---|---|
| 姓名 | 林澈（虚构人物） |
| 年龄 | 16 岁 |
| 身份 | 高一学生 |
| 设备 | 以手机为主，偶尔使用学校或家中的电脑 |
| 平台经验 | 熟练使用短视频、社交媒体、群聊和游戏社区 |
| 相关知识 | 第一次接触“信息茧房”“算法暴露”等概念 |
| 使用环境 | 放学后或睡前，常在消息提醒、同学聊天和短视频之间切换 |
| 核心特征 | 会快速判断内容是否值得继续看，但不习惯系统检查信息来源 |

**假设性代表语句：**

> “我知道网上的信息不一定都是真的，但如果好几个账号都在说，我一般会先觉得这件事大概是真的。”

---

## 行为｜Behaviours

- 快速浏览标题、截图和评论区，再决定是否继续阅读。
- 常用点赞量、转发量和评论区态度判断一个观点是否“主流”。
- 看到与朋友兴趣相近的内容，会直接转发到群聊讨论。
- 遇到争议事件时，可能搜索关键词，但通常只看排名靠前的结果。
- 很少主动追踪首发账号、原始聊天记录或完整上下文。
- 对游戏社区的语言和互动方式熟悉，愿意完成带有解密、收集和拼图反馈的短任务。
- 如果页面文字太多、术语太抽象或反馈太慢，容易退出或跳过。

## 目标｜Goals

### 直接目标

- 快速弄清楚游戏社区中的角色争议到底有哪些事实、观点和利益冲突。
- 判断热门帖子、历史证据和玩家感受分别能说明什么。
- 在不被说教的情况下，理解为什么一个热门观点不等于完整事实。
- 完成调查并获得明确、可执行的下一步建议。

### 长期目标

- 在转发或站队前，多做一次来源检查。
- 发现自己看到的“多数意见”可能只是同一信息被重复传播。
- 学会区分事实、观点和推测，同时保留独立判断。

## 痛点｜Pain Points

- “信息茧房”等术语陌生，可能误以为这是考试或人格评价。
- 容易把多个账号的相似说法当成多份独立证据。
- 对长篇说明、学术词汇和复杂评分缺乏耐心。
- 害怕选错答案后被系统评价为“不理性”或“容易被骗”。
- 页面状态不清楚时，不知道自己是否已经完成任务。
- 如果必须记住前一页大量信息，容易因消息提醒或切换应用而忘记。
- 发现自己最初判断可能有误时，可能产生防御心理，不愿继续。

## 数字习惯｜Digital Habits

| 习惯 | 可能影响 |
|---|---|
| 手机优先、单手操作 | 关键按钮和文字需要清晰、可点，不能依赖悬停 |
| 短时高频使用 | 每一步都应有明确目标，避免长时间无反馈 |
| 多任务切换 | 需要保存进度，并让用户容易恢复当前任务 |
| 依赖评论区和社交证明 | 需要让用户看到“高热度不等于独立证据” |
| 截图和转发多于保存链接 | 需要突出原始来源、时间线和上下文缺失 |
| 熟悉游戏与解密反馈 | “调查档案—收集证据—拼图归位”的隐喻容易理解 |

## 信任触发点｜Trust Triggers

- 清楚说明这不是心理测试，也不会给观点判对错。
- 清楚显示每份档案代表谁的视角，以及它提供了什么类型的证据。
- 将“事实”“观点”“推测”用熟悉的语言解释，并提供即时反馈。
- 允许返回、修改答案和重新开始。
- 说明系统为什么给出某项反馈，而不是只显示分数。
- 同时展示多个角色或立场，避免让用户感觉系统在强迫站队。
- 最终建议具体、可执行，例如“转发前打开原始来源”，而不是泛泛地说“提高媒介素养”。

## 核心任务场景｜Task Scenario

林澈在历史游戏社区看到一篇热门帖子：游戏新增了虚构的女性火炮指挥官林月，一些玩家认为角色不符合历史，而且游戏为了多元化放弃了真实性。帖子获得大量点赞和转发，但林澈还没有看过其他证据。

林澈从网站首页进入，没有老师或研究者指导。他需要：

1. 根据第一条说法形成初步判断；
2. 阅读资深玩家、历史学者、新玩家、游戏设计师和社区管理员五种视角；
3. 区分已知事实、合理推测和虚构说法；
4. 理解另一名玩家的原话，而不是只按群体立场解释；
5. 权衡历史准确性、玩家感受和游戏乐趣；
6. 使用完整信息作出最终判断；
7. 阅读一条与本次调查行为有关、能够执行的反思建议。

**任务成功标准：**

- 能说出“热门观点不等于事实”；
- 能区分历史证据、玩家感受和设计取舍；
- 能理解一个视角而不必同意它；
- 能在看完五份档案后重新考虑或更有依据地保留原判断；
- 能选择至少一个下次愿意执行的查证动作。

## 认知走查重点｜Cognitive Walkthrough

| 关键步骤 | Goal | Notice | Associate | Feedback |
|---|---|---|---|---|
| 开始调查 | 是否理解任务是调查信息传播，而不是接受测试？ | 是否看到清晰的开始入口？ | 是否知道开始后要调查什么？ | 是否明确进入第一项任务？ |
| 区分线索类型 | 是否愿意逐条判断？ | 是否看见可选择的线索和分类文件夹？ | 是否理解“已知、可能、虚构”的区别？ | 归档后是否知道当前状态仍可修改？ |
| 阅读五种视角 | 是否形成“继续补全案件”的子目标？ | 是否注意到下一块亮起的角色拼图？ | 是否理解不同角色会提供不同证据？ | 保存后是否看见角色碎片归位和进度变化？ |
| 理解他人观点 | 是否愿意理解而不是立刻站队？ | 是否看见原话和解释选项？ | 是否知道“理解”不等于“同意”？ | 选择后是否得到中性反馈，而非被判对错？ |
| 查看结果 | 是否愿意反思，而不是防御？ | 是否看到结果和建议？ | 是否理解结果描述的是本次行为？ | 是否得到可执行的下一步？ |

## 设计含义｜Design Implications

1. **使用青少年熟悉的语言。** 首次出现“信息茧房”时用一句话解释，并用“同一说法被重复转发”作为具体例子。
2. **让系统状态始终可见。** 显示当前步骤、已收集证据和五块拼图进度，减少用户对流程的猜测。
3. **优先识别而非回忆。** 将角色身份、当前任务和相关线索保持在当前界面可见，不要求用户记住前页内容。
4. **把反馈写成证据解释。** 说明这项选择反映了哪一种线索或取舍，避免只显示正确或错误。
5. **保护用户控制感。** 支持返回、修改、重新开始，并在中断后保留合理进度。
6. **避免人格化评分。** 结果页描述本次调查行为，不贴“容易被骗”“理性程度低”等标签。
7. **让视觉隐喻服务任务。** 档案、线绳、图钉和拼图用于表示来源关系、证据收集和视角归位；不能遮挡信息。
8. **提供新手引导但不过度解释。** 每页只说明当前目标；更详细帮助放在需要的位置。
9. **最终建议必须可执行。** 例如“查看一个不同角色的视角”“区分已知事实和推测”“在回复前再检查一份来源”。

## 研究假设｜Research Hypotheses

以下内容是待验证的预测，不代表真实青少年普遍如此：

- H1：游戏社区情境会比抽象新闻案例更容易促使 16 岁用户开始任务。
- H2：用户可能把高点赞和群体共识当成事实强度。
- H3：五角色拼图逐步归位，能帮助用户理解“一个案件需要多个视角”。
- H4：“反思档案”比“测试分数”更不容易引发被评价感。
- H5：明显的步骤进度和拼图归位反馈能降低中途退出。
- H6：青少年能理解事实与观点的区别，但可能在带有情绪判断的语句上犹豫。
- H7：用户是否采纳最终建议，可能更多受到同伴行为和使用情境影响，而不只取决于界面说明。

## 待验证问题｜Questions to Validate

### 通过可用性测试 / Cognitive Walkthrough 验证

1. 用户是否理解“调查”的目标，而不是把它当成知识考试？
2. 用户在哪一步第一次感到困惑：任务目标、按钮位置、术语，还是反馈？
3. 用户能否发现并理解五角色拼图的推进方式？
4. 用户是否把最终档案理解为本次行为反馈，而不是人格评价？
5. 中途被消息打断后，用户能否恢复到原来的任务位置？

### 通过情境调查 / Contextual Inquiry 验证

1. 青少年真实使用社交平台时，什么行为会触发他们打开评论区或搜索来源？
2. 他们把内容转发给朋友时，想确认事实、表达立场，还是维持群体互动？
3. 点赞量、账号身份、熟人转发和可核查证据，哪一种最能建立信任？
4. 截图、收藏、小号和群聊分别承担什么实际作用？
5. 他们在什么情况下愿意查看不同观点？什么情况下会直接退出？
6. 游戏社区案例是否符合真实经验，还是会限制原型向其他信息场景迁移？

## 研究使用说明

这份画像适合用于早期 **Cognitive Walkthrough**，帮助团队围绕一个具体用户预测认知断点。后续应通过真实青少年的 **Contextual Inquiry** 和可用性测试修正画像。

课堂汇报时应明确：

> 画像帮助我们提出可检查的风险假设，但不能证明问题发生的频率。Prediction is not prevalence.
